# إتاحة سطح الحساب للزائر

تقدّم `/account` سطحًا مشتركًا للحساب الحقيقي ومحفوظات الزائر المحلية، وليست دليل ملفات شخصية عامة. يُسمح بطلب الصفحة نفسها بلا كوكي كي لا يُعاد الزائر الجديد إلى `/login` عند فتح وجهة «الحساب» أو العودة إليها.

الاستثناء محصور في المسار الدقيق `/account`، ويشمل التنقل المعتاد و`HEAD` وRSC. لا يفتح `/account/*` ولا `/settings` ولا `/contribute` ولا `/admin`. لا يغيّر هذا صلاحيات واجهات البيانات أو تسجيل الدخول أو إعدادات النشر؛ تبقى واجهات البيانات الخاصة مسؤولة عن التحقق من هوية الجلسة.

## صلة التغيير بـ PR #28

كان PR #28 مفتوحًا كمسودة منفصلة عند بدء هذا العمل، ومضمونه يفتح سطح `/account` للزائر مع اختبارات بوابة وفحص نشر. نُقلت هذه الفكرة المحدودة واختباراتها إلى فرع التطوير الحالي لتكون ضمن مجموعة الإصلاحات المتكاملة، مع إبقاء PR #28 مفتوحًا وغير معدّل؛ لم يُدمج أو يُغلق تلقائيًا. يُرجى مراجعة تداخل النطاق بين الطلبين عند مراجعة PR الجديد.

## التحقق

- `/account` بلا كوكي: `200`، سطح الزائر ومبدّل المحفوظات/المساهمات، بلا بريد حساب.
- `/account` مع أو بلا كوكي زائر، بما في ذلك `HEAD` وRSC: لا إحالة إلى الدخول.
- `/account/submissions` و`/settings` و`/contribute` و`/admin`: تبقى محمية كما كانت.
- واجهات البيانات الخاصة تظل خاضعة لاختبارات التفويض الموجودة؛ لم تُغيّر معالجاتها.
