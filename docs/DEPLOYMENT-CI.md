# فحوص الجودة والتحقق من معاينة Render

يعرّف `.github/workflows/deploy.yml` فحوص الجودة والتحقق الحي من معاينة Render. **هذا الـworkflow لا ينشر التطبيق إلى Render ولا يغيّر إعداداته**؛ النشر إلى المعاينة تديره آلية Render خارج سير العمل. المرجع التنفيذي للعقد الحي هو `scripts/verify-deployment.mjs`.

## ما الذي ينفذه الـworkflow؟

| الوظيفة | متى تعمل | ما تنفذه |
|---|---|---|
| فحوص الجودة والبناء | عند طلب دمج إلى `main`، وعند الدفع إلى `main` مع تجاهل تغييرات Markdown و`docs/**` و`verification/**` في الدفع فقط | Node.js 22 وpnpm المحدد في `package.json`، تثبيت FFmpeg، `pnpm install --frozen-lockfile`، ثم `pnpm typecheck` و`pnpm format:check` و`pnpm test` و`pnpm build`. |
| التحقق من معاينة Render | بعد الدفع إلى `main` فقط، أو عند التشغيل اليدوي؛ لا يعمل على طلبات الدمج | إيقاظ محدود للمعاينة عند الحاجة، انتظار الإصدار المتوقع عند التشغيل العادي، ثم فحوص HTTP للـhealth والمسارات والواجهات العامة والوسائط. لا يتضمن خطوة نشر. |

على طلبات الدمج، تعمل الجودة والبناء ولا يجري فحص المعاينة الحية. بعد الدفع إلى `main`، يفترض التحقق أن Render ينشر وفق إعداداته الخارجية، ثم يقارن الإصدار المعلن في `/api/health` مع التزام التشغيل. نجاح هذا التحقق دليل على نتيجة ذلك التشغيل فقط، وليس ضمانًا دائمًا لحالة الخدمة.

## التشغيل اليدوي

من GitHub Actions اختر سير «النشر والتحقق في المعاينة» ثم `Run workflow`:

- `verify_only = false` (الافتراضي): ينفذ فحوص الجودة والبناء ثم ينتظر الإصدار المقابل للتشغيل قبل فحص المعاينة.
- `verify_only = true`: يتجاوز وظيفة الجودة وينفذ تحققًا على ما هو منشور حاليًا، بلا انتظار إصدار جديد. لا ينشر هذا الخيار التطبيق.

يمكن أيضًا تشغيل عقد الفحص قراءةً فقط من بيئة محلية أو CI:

```bash
node scripts/verify-deployment.mjs https://yemreact-preview.onrender.com
node scripts/verify-deployment.mjs http://localhost:3000
node scripts/verify-deployment.mjs "$URL" --expect-revision "$GITHUB_SHA" --wait 900 --poll 15
```

يدعم السكربت `--wait` و`--poll` و`--warm` و`--json` و`--request-timeout`؛ راجع التعليقات في الملف لتفاصيل الخيارات. يعرض كل فحص مستقلًا ولا يخفف شروطه عند تعذر إيقاظ الخدمة. يجب إجراء فحوص المتصفح والرفع التي تكتب بيانات على قاعدة اختبار منفصلة فقط، لا على قاعدة الخدمة الحية.

## متغيرات GitHub الاختيارية

المسار الافتراضي هو معاينة Render المحددة في workflow؛ ولا يتطلب سير الفحوص أسرار نشر أو أداة نشر خارجية.

| المتغير | الاستخدام |
|---|---|
| `PREVIEW_BASE_URL` | GitHub Actions Variable اختيارية لتجاوز عنوان المعاينة الافتراضي في فحوص HTTP. |
| `NEXT_PUBLIC_SITE_URL` | Variable اختيارية لقيمة عنوان الموقع وقت البناء؛ إن لم تُحدد، يستخدم workflow عنوان المعاينة نفسه. |
| `VERIFY_WAIT_SECONDS` | Variable اختيارية لمهلة انتظار الإصدار، بالثواني؛ القيمة الافتراضية 900. |

لا يحتاج workflow الحالي إلى أسرار نشر. مفاتيح OAuth وأسرار التطبيق تخص بيئة تشغيل الاستضافة، وتُدار هناك وفق `SOCIAL-AUTH.md`؛ لا تُضفها إلى السجلات أو المستودع. لا يغيّر هذا الدليل إعدادات Render، ولا يمنح إذنًا بنشر يدوي أو تغيير خدمة.

## نطاق التحقق وحدوده

يتحقق السكربت من استجابة بوابة الجذر، وHTML العربي للمكتبة، وعقد `/api/health` وكتالوج الرياكشنات، واتساق sitemap وrobots مع أصل الموقع، وترويسات أمان أساسية، وصفحة تفصيل موجودة ومسار رمز غير موجود، وبوابة الزائر/الحساب والإعدادات، وواجهات المحفوظات، وتسليم ملف وسائط، بما في ذلك Range عند انطباقه. قائمة الفحوص الفعلية ورسائلها هي `scripts/verify-deployment.mjs`.

لا يثبت الـworkflow تسجيل OAuth لدى مزوّد خارجي، ولا يفحص يدويًا مسارات المتصفح الموثقة في `docs/QUALITY-REPORT.md`، ولا يبني صورة Docker، ولا يختبر النسخ الاحتياطي والاستعادة أو إعدادات التخزين من لوحة Render. نجاح `pnpm build` هو بناء Next.js وفق الأمر في المستودع، وليس اختبارًا لعملية نشر أو بناء حاوية كاملة.

## قراءة النتائج

في تشغيل GitHub Actions، راجع نتيجتي «فحوص الجودة والبناء» و«التحقق من معاينة Render». تحفظ وظيفة التحقق تقرير JSON باسم `render-preview-verification` عند إنتاجه؛ كما تظهر الأخطاء والتحذيرات المهمة في ملخص الوظيفة. endpoint `/api/health` يعرض المستوى والفحوص العامة وأعدادًا محدودة من دون عرض أسرار OAuth أو بيانات الحساب.

إذا فشل التحقق، راجع الإصدار المعلن، ثم أصل الفشل المحدد وترويسات/استجابات المسار. لا تعتبر `warn` مساويًا لفشل الخدمة: قد يدل على إعداد اختياري ناقص، مثل عدم تهيئة OAuth أو عدم وجود مدير بعد. ويجب تفسير أي عدّاد وفق الدور والصيغة اللذين يستخدمهما الكود الحالي.
